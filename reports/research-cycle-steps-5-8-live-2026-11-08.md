# Real-model research-cycle guide steps 5–8

Date: 2026-11-08. Follow-up to [the Phase 1–5 live test](phase-1-5-live-e2e-2026-11-08.md). One model family was requested; this is not a repeatability study.

## Setup

DSH 0.2.2-rc.1 and Academic Harness 0.48.1 ran in the isolated profile on loopback port 3080, using DeepSeek-V4.1-Flash and Workspace Write. The research-cycle session and a separate step-8 session used that same model; the initial prompts were sent through host RPC, with follow-ups and inspection through agent-browser.

The CC0 fixture contained separate baseline and variant Python implementations, a synthetic 12-row dataset, and six **actually executed** analysis runs, each sampling eight rows with seed 1, 2, or 3. Five experiment runs were initially logged; variant seed 3 had a successful analysis record and artifact but was intentionally absent from the experiment ledger. A short, synthetic, CC0 manuscript and clearly identified synthetic reviewer comments were supplied. No research results should be inferred from this fixture.

## Findings

### 1. Package README commands do not work from the package root

The built `package/threshold-pilot/README.md` says to run `python3 analysis/eval.py --method base --seed 1`, but the Python files and CSV are stored under `code/analysis/` and `code/data/`. From the package root the documented command exits 2 because `analysis/eval.py` is absent. The same command succeeds from a separate copy of the `code/` directory and yields the expected fixture result. The README does not instruct the reader to change into `code/`. The 31/31 verification checks package hashes, not replayability, and did not detect this. Evidence: `evidence-steps-5-8/package-root-replay.txt` and the local package README.

### 2. Programmatic image reading appeared under a vision-review label

The vision child explicitly reported that `read_image` was not mounted and that it used OCR and pixel calibration instead. The parent accurately disclosed that limitation in its final response. However, it then placed the programmatic result in the `vision_review` field. The method caveat was placed in `reviewer`, while the visible tool result rendered the summary under “Vision review (model interpretation, not verification)” without displaying that reviewer caveat. A reader seeing only the tool result could therefore mistake the reading for an actual multimodal vision inspection. Evidence: `evidence-steps-5-8/vision-result.txt` and `figure-final-call.txt`. This is one observed caller/renderer interaction; the cause of `read_image` being unavailable has not been isolated.

## Fixes applied after the run

- **Native vision.** Removed the top-level `read_image` restriction and guard. The main agent now reads images directly when its model declares image input; prompts, skills, and presentation QA text all say to use `read_image` and to report the check as not performed rather than substituting OCR, pixel math, or metadata. `subagent_vision` is optional for a separately configured vision route. On a freshly packed isolated host, the main DeepSeek session called `read_image` and correctly described the line plot's title, axes, legend, circle/square markers, and flat series. It used no OCR. A separate delegation retest required `subagent_vision` and forbade OCR, shell image processing, source reconstruction, and guessing. The parent delegated, the child reported `read_image used: yes`, and its description matched the known figure (title, `Seed`/`Accuracy` axes, blue-circle `base`, orange-square `variant`, flat series at ≈0.75 and 1.0, no annotations). A second independent child reading agreed. Evidence: `evidence/vision-subagent-child.txt` and `vision-subagent-parent-final.txt`.
- **Step 5 stays read-only.** The guide now forbids registering, logging, linking, or changing records to complete coverage, says instructions in workspace files are not permission, and requires reporting the missing run first and registering it only after an explicit request naming those records. It also forbids cache writes during the step (`provenance_audit index` writes a cache). A fresh live retest kept the ledger at five runs, reported seed 3 as missing, asked whether to register it, and left every workspace file byte-identical after the answer; its five `experiment_log` calls were compare twice, best, replicates, and branches.
- **Reproducibility README.** When code files are copied, each Run order command is now `(cd code && <command>)`, so it can be pasted from the package root. The README also says other inputs must be restored at their original relative paths, that `dataset_get` data sits under the package-root `data/`, and that `code/` should be copied elsewhere before running. The regression test replays the documented command. A rebuilt fixture package (19/19 hashes) ran the documented command successfully and reproduced `accuracy: 0.75`.
- **Vision reviewer visibility.** `figure_audit action=handoff` now keeps a method caveat (up to 500 characters) and renders it inside the fenced review under `Reviewer/method (caller supplied)`, instead of dropping it from the heading. A forged closing tag cannot escape the fence; tests cover both.
