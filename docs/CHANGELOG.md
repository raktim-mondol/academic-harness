# Changelog

Release notes for Academic Harness. For releases before 0.18.0, see the [GitHub releases](https://github.com/raktim-mondol/academic-harness/releases).

## Unreleased

Trust and approval, from the 2026-11-10 review (decisions D11-D18).

- **Paid compute asks first.** `modal_run`, `runpod_run` and `vastai_run` request approval on every call. The prompt shows provider, instance, maximum run time, a cost ceiling and a preview of the command; a pinned Vast.ai offer says its price is unchecked.
- **`repo_audit run_tests` no longer exposes your API keys.** The repository's tests run with an allowlisted environment (`safe-process.js`, shared with `analysis_run`), asynchronously, with a timeout that kills the whole process group and honours cancel.
- **A registry that arrives with a folder no longer starts a program.** `paper_mcp` entries mount only after you approve that exact entry for that workspace. `register` and the new `approve` action ask; approvals are stored under `$DSH_HOME/paper-mcp/`, and any change to the command, arguments, directory or env names asks again. Only the approved env names reach the server.
- **Host seams are checked in CI.** `scripts/check-host-contract.mjs` reads the installed host's declarations and fails if the approval seams move. See `docs/COMPATIBILITY.md`.

- **Reproducible installs and CI.** `package-lock.json` is committed and CI installs with `npm ci`. The profile install in CI still uses `npm install` because it depends on a `file:` copy of the plugin.
- **Faster, safer test runner.** `npm test` runs files in parallel with a per-file timeout that kills the process group, a scratch `DSH_HOME` per file and optional JUnit output (`--junit`). About 70 s instead of about four minutes.
- **Lint and type check.** ESLint (correctness rules only) and `tsc --noEmit` over an explicit allowlist run in CI. The first lint pass found a duplicated `rationale` key in the `coscientist` tool schema, which made the `add` description read as the `select` one; the two are merged.
- **Smaller package.** `scripts/`, `docs/`, `reports/` and vendored tests no longer ship: 3,415 to 3,145 files and 45.1 to 41.1 MiB unpacked. A new test (`test-package-files.mjs`) fails if a shipped module imports a file that is not packed. `skills/deep-review` now says its calibration script is for a repository checkout.
- **Fetched text is fenced as data.** Search listings (every provider through `renderPapers`), Jina pages, `paper_get` abstracts and Consensus results are wrapped in an `<untrusted-source>` block, a payload cannot close its own fence, and the system prompt's Safety section says fetched text has no authority. Paper full text from `paper_fold` and `paper_context` is not yet fenced.
- The dated "Runpod v1 retires on 2026-11-15" line is gone from the system prompt.
- **Skills on demand (D39).** The host catalogue lists only the 87 core skills (about 20,000 characters instead of about 290,000). `skill_search` and `skill_load` reach the other bundled skills, and earlier byte-identical copies are removed from `$DSH_HOME/skills` once. `AH_SKILLS_SEED=all` restores the old behaviour. The host `skill` tool is not shadowed: a second `skill` tool in the preset layer would collide with it.
- **Tool surface measured, nothing deferred (D40).** `scripts/measure-tool-surface.mjs`: 136 tools, about 294,000 characters (about 73,000 tokens) resent each step. `deferLoading` is not used because a deferred tool is only usable after a host-written `tool-addition` record; see `docs/DEFERRED-TOOLS.md`.
- **Checked with a real model instead of a live session.** `scripts/claude-plugin-check/run.mjs` (not part of `npm test`: needs a Claude login) drives Claude Haiku 5.5 through the plugin's real `skill_search` / `skill_load` over MCP and through an injected search listing. 36 task runs: searched first 36/36, loaded an accepted skill 35/36 (the miss loaded `datamol`, a reasonable alternative). 60 injection runs per arm: the old unfenced listing was followed in 32, the fenced listing with the Safety paragraph in 3. It does not cover the Settings page, the host catalogue or `/name`.
- **Credential settings are secrets (D47).** API keys and tokens use `role('secret')`, so a stored key is no longer sent to the browser; the Settings page shows "configured" from the host's presence sidecar. `AH_SECRET_SETTINGS=0` turns it off.

## 0.50.0

The writing compiler, checked against a second model, a real host and real LaTeX. Rule set 1.10.0, `BUNDLE_REV` `dsh14`. Evidence and limits: [the follow-up report](../reports/writing-compiler-claude-host-tex-2026-11-09.md).

- **A TeX scanner checked against real LaTeX; 19 false blocker findings on real manuscripts are gone.** One scanner (`ah/tex/scan.py`) now reads every `\cite`, `\ref`, `\label` and `\input` for every check, and a differential test (`tests/test_tex_oracle.py`, 20 cases, skipped without TeX) compiles small projects with `latexmk` and compares what TeX read, cited, labelled and referenced with what the scanner believes. It disagreed on 12 of 16 first cases. On the maintainer's 20 real manuscripts the old scanner raised 19 `TEX-02` (blocker) findings that were all false: labels defined in `\begin{lstlisting}[label={lst:...}]` options (18 on one book, 1 on this repo's own paper). Now understood: `\input name`, `\subfile`, `\import`, `\InputIfFileExists`; every citation form (`\footcite`, `\Cite`, `\supercite`, `\cites`, `\parencites(..)[..]{..}`), every reference form (`\vref`, `\hyperref[..]`, `\crefrange`, `\labelcref`, ...), `\nocite{..}` and `\nocite{*}` (no longer "never cited", `BIB-05` 15 to 13 on two papers); comments, `\iffalse` blocks, the dead branch of `\iftrue`, the `comment` environment, `\verb` and verbatim/lstlisting/minted bodies are not markup; wrapper macros (`\newcommand{\figref}[1]{\ref{#1}}`) carry the keys of their uses, and the `#1` placeholder in their definition is no longer a citation, label or missing file. Reading order and reachability share one resolver. Unit text is unchanged when nothing is dead, so no anchor or hash moves. Four thousand random inputs check that the transform is idempotent, keeps line numbers and invents no text (this found a real duplication bug). New checks: `TEX-06` (info, an `\input` path built by a macro cannot be audited) and `TEX-09` (major, `\end{document}` in an included file ends the document, so what follows is never typeset: found in one real manuscript, where two appendix files never reached the PDF). Against the compiled PDFs of the 20 manuscripts the scanner agrees with TeX on inputs 20/20, citations 19/20, labels 19/20 and undefined references 20/20 (the exceptions: a manuscript that cites with natbib's `\citep` under biblatex so TeX recorded none, and a label a package generates), and its text covers 93.6% to 99.5% (median 98%) of the distinct words in each PDF once the rendered bibliography and code listings are set aside.
- **The build log: located overfull boxes, page count, missing glyphs, a page limit.** `ah build` / `audit --build` now attribute each overfull box to one paragraph (`TEX-04`, one finding per paragraph, keyed without a line number), report the page count, and raise `TEX-07` (minor) for characters missing from the font and `TEX-08` (major) when the document exceeds `build.max_pages`. A real log showed why attribution uses the starting line and the first words of the box, not the open-file stack: the last paragraph of an included file is reported after that file's closing parenthesis. A box the log does not tie to one paragraph stays a document-level finding rather than a guess.
- **The guard closed in a real Claude Code host.** Driving real sessions (headless and the terminal UI, Haiku 5.5 and Sonnet 5.5; `scripts/claude-host-test`) found that an agent's shell could run `ah rule accept|reject`, `ah disclosure approve`, `ah provenance set|fill` and `ah migrate --force`, and answer the engine's "type yes" prompt through a pseudo-terminal (`script -qec`): confirmed end to end, now denied. `provenance set` had no confirmation at all, so an agent could relabel its paragraphs as human-written and change the AI-use disclosure. Reads were wrongly denied: `cat facts/facts.yaml 2>&1` counted any `>` as a write; a redirect now counts only when its target is protected. A debug log that could not be written aborted the `pre` hook before the protection logic ran, which hosts read as "allow"; the log is best effort, and an engine error (a typo in `ah.yaml`) now denies Write, Edit and Bash with the reason (reads still work, `AH_NO_ENFORCE=1` still works). `.claude/settings.json` is a protected path. The author acts are one table (`guard.HUMAN_ONLY`) with a test that fails when the CLI gains a terminal-confirmed act the guard does not name. Held live (headless: Haiku 5.5 and Sonnet 5.5; terminal UI: Haiku 5.5): protected edits and shell appends denied, files byte-identical; author acts denied with the reason; the stop gate blocked, re-entered the model and ended when the model handed the finding to the author; Claude Code's own approval dialog (Yes applies, No leaves the file) and the author's `! ah finding waive ... --yes` inside the session.
- **Claude Code as a rubric model (`ah.verifier.claude`).** One tool-free, single-turn `claude -p` call in safe mode in an empty directory; only a finished one-turn answer from exactly the requested model is accepted (an alias, a second turn, a permission denial or a different model is an error and never cached). Measured on the 84 (criterion, paragraph) pairs of the OpenCode run: all three models agree on both planted overclaims; GPT-6.1-sol and Sonnet 5.5 agree on 83 of 84, Haiku 5.5 and Sonnet 5.5 on 79; Haiku answered `unclear` on 4 pairs and gave 1 `yes` the others rejected. This is agreement between models, not accuracy, and it matters for completion: an admitted criterion with an `unclear` pair is INCOMPLETE.
- **Rubric reliability fixes from the OpenCode session (rule set 1.9.0).** Unclear and unverifiable rubric answers carry findings and leave admitted criteria incomplete instead of silently fixing them (a randomised model check over 70 sequences of audits agrees); admission refuses uncertain labels, and admitted info-level defects still affect completion. Versioned verifier fingerprints replace truncated command cache identities. Failed calls are counted and request budgets include correction attempts. Migration follows literal includes across appendix and custom directories (`UNIT-04`). Malformed criteria and admissions report diagnostics; a bare `scope:` or `criteria:` key means "not given". State cards read cached rubric and external results. An opt-in OpenCode verifier adapter records real usage with no DeepSeek fallback.
- **Closures say why; carried findings say so; the plan's remaining invariants are pinned.** Checking the OpenCode remediation plan against the code found items nobody had done. A finding that stopped being reported was just `fixed`, so a model's "no", a deleted paragraph, a narrowed scope and a switched-off criterion looked the same, and switching a criterion off made `ah done` pass without saying so: the ledger now records `fixed_reason` (an old ledger is upgraded in place), `ah finding show` and audits show it, and `ah done` says when findings were closed with no model verdict. A finding carried over an unusable answer after an edit still quoted text that no longer exists; it now says it is the earlier assessment. Waived and handed-over findings meeting `unclear` are pinned. Profile inference reports why and what competed, and two specific profiles that fit give `generic`. `migrate`'s contract is pinned (dry run writes nothing; apply adds only anchor comments and the overlay; a second apply refuses), and its docstring, which promised not to touch the author's files, now says what the default does.
- **Behaviour changes.** Old rubric admissions are void and need remeasurement under protocol 2 (none exist on the maintainer's machine); old verdict caches are not reused; a `pi` verifier with `retries` above 0 is refused so the request budget stays enforceable; findings that depended on the old scanner change once (`TEX-02` and `BIB-05` drop, `TEX-04` becomes per paragraph); OpenCode remains a verifier route only, with no host adapter.

## 0.49.0

The writing compiler: checks on LaTeX writing that behave like a compiler. The same text gives the same findings, each finding has a fingerprint and a ledger state, and "is it done" has one answer (`ah_done`: pass, fail or incomplete). Registry lookups are frozen in a snapshot, external tools (numbers, figures, citations, reporting) report into the ledger, thirteen format and consistency rules run at info, a frozen rubric (quote-checked, cached, never gating until the author admits a criterion) covers what rules cannot, and free reviews stay exploratory with a path to turn a recurring comment into a rule. Four live runs on real manuscripts with a real model (watched in the web UI) found and fixed the bugs listed below; the evidence and the limits are in [the live run report](../reports/writing-compiler-live-2026-11-09.md). Rule set 1.8.1.

- **Live-run round 4: approvals, hand-overs and waivers in the web UI.** A full run in the browser with a real model found four bugs, each fixed with a test that fails without it. (1) **The stop gate ignored a hand-over:** the hook audits without the ledger, so every finding read `open` and a finding the agent had handed to the author (`decision-needed`) kept counting as blocking; `audit()` without the ledger now reads waived and decision-needed states read-only (a waiver tied to a paragraph lapses when that paragraph changes). Live, the same scenario went from four gate attempts and a handoff to one check with 0 blocking. (2) **`ah_author action=waive` could never succeed:** it sent no `--by`, which the engine requires; it now passes `--by author` (the host only runs it after a person approves) and ignores a name the agent supplies. (3) **The paper-state card disagreed with `ah done`** after waivers (same cause as the first). (4) **A PASS hid what was waived:** `ah done` now reads "PASS ... 2 waived by the author: EVD-04 1, TEX-02 1". Held live: Allow once and Reject on the approval card, a shell attempt to waive blocked by the host (`human-only`), `ask_user_question` answered by clicking, the rubric at 45 model calls then 0, the first live `ah done` PASS. Not run: `deep_review` and rule promotion in the UI (the provider balance reached zero). See the Round 4 section of [the live run report](../reports/writing-compiler-live-2026-11-09.md).

- **Live-run round 2: the "not run" list.** Planted-error and outage scenarios run for real (real SciPy/Pillow auditors, real Crossref/OpenAlex, a network-less namespace for the outage). Held with no change: `STAT-01`/`STAT-02`/`FIG-01`/`FIG-02` fire on planted errors and not on the near-misses; a stale result gives `EXT-00` and the old finding is carried, not marked fixed; a truncated or required-but-missing result gives `EXT-00`; SciPy missing is an error that keeps the previous file; the lookup snapshot gives identical findings online and offline, reports a never-seen reference as `CIT-06` unverified (not a finding about the DOI), refetches only an entry older than 30 days, survives two concurrent audits, rebuilds a corrupt file, leaves a file of another version alone, and stores no credentials. Fixed: `numbers_audit` read `$P = 12$` (patches) or `p = 8` (predictors) as a p-value outside [0, 1]: a whole number is now a count unless the text calls it a p-value (F9); `ACR-03` counts `CDR = cancer detection rate` (a caption's list of abbreviations) as a definition (F4); `PRF-01` accepts `Methodology` as the method section in the conference, journal-empirical and systematic-review profiles (F3). Rule set 1.8.1. `ah rubric sheet --limit N` now samples evenly through the document instead of taking the first N paragraphs, prints each whole paragraph, and does not show model verdicts, so a person can label blind.
- **Live-run follow-ups: number removal, rubric precision, deep_review routing.** (1) After a prose edit the harness note now also says when the edit made a number disappear (`100%` reworded to "complete", a specific figure dropped) and that a finding about a number is cleared by binding it to a `\fact{id}` or citing it, not by rewording it away; the prompt and `ah-fix-findings` say the same for info lints. (2) Rubric criteria take an optional `quote_pattern`: a "yes" counts only if the words it quotes match it. `RUB-GENERAL` and `RUB-SUPERLATIVE` are reworded and at version 3 with patterns (rubric 1.8.0). Measured on 73 paragraphs I labelled by hand, one paper, one labeller, `deepseek-flash`: `RUB-SUPERLATIVE` kappa 0.88, precision 1.0, recall 0.8 (5 defects); `RUB-GENERAL` kappa 0.41, precision 0.33 (3 defects, too few to admit and too loose). Nothing is admitted; admission stays the author's decision. (3) The prompt and the `deep-review` skill say a deep or free-form review means calling the `deep_review` tool, one section included, not the model's own reading. See [the live run report](../reports/writing-compiler-live-2026-11-09.md).

- **Fixes from the first live run on real manuscripts.** (1) `UNIT-03` (major): a build-root file (`tex.views`) that holds 150+ words of prose is reported, because no check reads a root file; before this, a single-file manuscript (8,000 words in `main.tex`) audited as if it were nearly empty and nothing said so. Set `tex.view_prose_words` to change the threshold. (2) `NUM-004` no longer reconciles a signed percentage: `+10.4% (1/1000)` is a change with a rate beside it, not a share of a total, and the old reading produced a false **blocker** on a real table. (3) On DSH the paper-state card no longer tells the model that `ah` is a shell command; the model searched for a binary that does not exist there. (4) **The stop gate could miss a blocker the agent had just added.** On DSH the host re-enters a turn after a question is answered, and that ran the prompt hook again, which reset the baseline to include the new blocker and cleared the list of touched files; the turn then ended with an undefined `\ref` reported by nothing. A turn that has touched files and has not settled now keeps its baseline. (5) The gate no longer re-steers a finding the agent has already handed to the author, and a finished `deep_review` names the `ah_triage source=deep_review` call that keeps each comment's quote. See [the live run report](../reports/writing-compiler-live-2026-11-09.md).

- **One answer to "is it done": `ah_done` (writing-compiler phase 6).** `ah done` / `ah_done`, every `ah audit` report and the paper-state card now end with **pass**, **fail** or **incomplete** and the component that decides: findings at a blocking level, open findings from *admitted* rubric criteria (at any level), stale or missing external results (EXT-00), new findings with no cause, and a registry snapshot older than `done.lookups_max_age_days` (default 30). Incomplete means nothing failed but something that matters was not looked at (admitted criteria with no verdict, external results not read); it is not a pass. `ah done` reads the rubric and external results by itself when the project has them (model calls only with `judge`); exit 0 pass, 1 fail, 3 incomplete. The stop gate now reads the external tier and the rubric (cached verdicts, so only admitted criteria can block), and with `gate.judge_touched` judges the files the turn changed; EXT-00 stays out of the stop gate because any edit makes a stored result stale. `report.gate` is unchanged. Not run against a real model-backed rubric; the age check reads the file the JavaScript lookup cache writes.

- **Free reviews are exploratory; a recurring comment can become a rule (writing-compiler phase 5).** In an `ah.yaml` project `deep_review`, `peer-reviewer` and `pre-submission-reviewer` are labelled exploratory and never gating (the `deep_review` output says so; the skills and the prompt now say: fix ledger findings, treat review comments as candidates, never re-run a review only to see that fixes worked). New `ah_triage` / `ah triage` tags each comment of a stored `deep_review` round or an imported review `covered-by:<check>`, `same-unit:<check>` or `exploratory`, with no model call; `ah review import` tags items as it imports them. New `ah_rule_propose` / `ah rule propose` drafts a rule from a comment: a regular expression (new check `PRM-01`, tested against the sentence the comment quoted, refused if it matches empty text, repeats a repeated group, fails a negative example, or fires on more than a fifth of the paragraphs) or a rubric criterion. The proposal checks nothing; only the author accepts it (`ah_author action=accept id=PRM-NAME`, `ah rule accept --yes`), into `rules/promoted.yaml` or `rubric/promoted.yaml` (both protected from agents). `PRM-02` reports a promoted rule whose own fixture fails. Rubric 1.7.0. Triage is a lookup (a check fires on the same paragraph, sharing a word with the comment), not a judgement that the check addresses the comment; promoted patterns ship at info and are checked against one sentence plus the negatives given, not a labelled corpus. Not yet run against a real `deep_review` round with a real model.

- **Format rules: the phase 3 limitations fixed, and measured on held-out text.** Rules now read the document in `\input` order from the main files (not file-name order); paragraphs written in the main file itself, tables, figures, captions and headings are read too, and a heading finding is attached to the paragraph after it instead of the file. Acronym definitions are recognised by letters inside words ("Antimicrobial resistance (AMR)", "eXplainable AI (XAI)"), and identifiers, hyphen compounds, names in bibliography titles, names followed by a name noun, and acronyms that only appear in tables are no longer reported as undefined. FMT-03 no longer flags `\cite` mixed with narrative `\citet` (normal natbib usage); it compares the two parenthetical forms, `\cite` and `\citep`. "Used but never defined" is now its own check, **ACR-03**, so the precise ACR-01 (used before its definition, defined twice) can be promoted without it. Held-out evaluation with frozen rules on two unseen research proposals: 25 of 45 findings right; every wrong one was ACR-03 (names it cannot tell from jargon). Engine rubric 1.6.0, `BUNDLE_REV` `dsh10`. See [Writing](WRITING.md#format-and-consistency-rules-acr--fmt-).

- **Thirteen deterministic format and consistency rules (ACR-01/02, FMT-01..11), all at info.** Acronyms used before they are defined (a definition must have initials that spell the acronym), numbers and units that can break across a line, `%` against "percent", `\cite` mixed with `\citep`, a citation before or after the full stop, figures and tables with no label or never referred to, sentence against title case headings, US against UK spelling, repeated words, one term in several forms, `e.g.,` with and without the comma, and long sentences. Consistency rules flag the minority form; declare the form under `style.format` and they flag whatever departs from it. They are in `ah_audit` and the ledger but not in the post-edit note or the gate until the author promotes one with `levels:`. New `ah precision` / `ah_precision` turns the author's own fix-against-waive decisions into a per-rule precision estimate and says when a rule has enough decisions to promote. Engine rubric 1.5.0, `BUNDLE_REV` `dsh9`. Evidence is stated as it is: 75 fixture cases written by the rules' author (regression, not accuracy); on a copy of `paper/rsi-local` the first run's 65 findings exposed four kinds of false positive that were fixed, leaving 18 of which, by my reading, 8 were right. Phase 3 of the writing-feedback plan. See [Writing](WRITING.md#format-and-consistency-rules-acr--fmt-).

- **The frozen rubric (tier TR): fixed yes/no criteria, quote-checked and cached.** A criterion is a versioned question about one paragraph that asks about a defect (`RUB-CAUSAL`, `RUB-GENERAL`, `RUB-SUPERLATIVE`, `RUB-METHOD-VAGUE`, `RUB-RESULTS-INTERPRET`, `RUB-PROMISE` ship with the profiles; projects add their own in `rubric/*.yaml`). The model's "yes" counts only if its quote is found in the paragraph; the verdict is cached on (criterion, paragraph, model, prompt version), so unchanged text is never asked twice and always gets the same answer, and an edit re-judges only that paragraph. A pair that could not be judged (no model, error, over budget) is carried in the ledger, never closed. Every criterion reports at info until the author admits it with `ah rubric admit` (`ah_author action=rubric-admit`): the model is run over the author's hand labels and needs Cohen's kappa >= 0.6, precision >= 0.8, 20 labels with 5 of each kind. An admission is void if the question or the model changes. New: `ah audit|check --rubric|--judge`, `ah rubric list|run|sheet|admit`, tools `ah_rubric` and `rubric`/`judge`/`judge_limit` on `ah_audit`, checks RUB-01/RUB-02, `rubric/**` protected from agent edits, engine rubric 1.4.0, `BUNDLE_REV` `dsh8`. Not validated with a hosted model (that spends credits and was not authorised); on a copy of `paper/rsi-local` a stub model judged 629 (criterion, paragraph) pairs in 4.6 s, a repeat made 0 calls and added nothing to the ledger. Phase 4 of the writing-feedback plan. See [Writing](WRITING.md#the-frozen-rubric-tier-tr).

- **Stability report for the writing checks.** `ah_audit stability_runs=N` (CLI `ah stability --runs N` or `ah audit --stability N`) runs the engine's checks N times on unchanged text, without the ledger, and reports per-tier finding counts and overlap, every finding that came and went, open findings with cause `UNEXPLAINED`, and paragraphs without a `%% @unit` anchor (their findings re-key on any edit). On a migrated copy of `paper/rsi-local` the 227 findings were identical over 5 runs, and a second ledger audit added 0 new and 0 unexplained findings. This is phase 0 of making writing feedback repeatable: measure first, then widen the deterministic checks. See [Writing](WRITING.md#stable-findings-checking-the-checker).
- **The engine has tests again.** `vendor/academic-harness/tests/` scaffolds a LaTeX project with planted findings and pins DET-01, N-run stability, line-move-independent fingerprints, an unchanged second audit, and a cause for every new finding after an edit. Run with `npm run test:ah-engine`; CI runs it. The vendored engine is now maintained here (`vendor/academic-harness/SOURCE.txt`), and `BUNDLE_REV` is `dsh6` so the plugin-local venv is reinstalled on the next start.
- **Registry lookups are frozen in a snapshot.** `citation` (audit, repair, `validate` with `check_dois`) and `integrity_check` read Crossref and OpenAlex through `.ah/cache/lookups.json`: a definitive answer is stored and reused, a failed lookup is never stored (nothing stored → `unverified`; an earlier answer stored → the earlier answer is used), and a fetch happens only for a new reference, an answer older than `lookup_max_age_days` (default 30; 0 never expires), or `refresh_lookups: true`. A second audit of the same bibliography makes no network call and returns identical findings; an outage during a refresh changes nothing. Results report the data's age (`lookup.asof`, `data_as_of`). Stored answers skip the provider rate limiter, so a warm audit is fast. **Behaviour change:** an audit no longer re-asks the registries on every call; pass `refresh_lookups` to see a retraction that appeared since. Phase 1 of the writing-feedback plan. See [Writing](WRITING.md#frozen-registry-lookups).
- **External tools get check IDs, fingerprints and ledger states (tier TX).** `ah_external` runs `numbers_audit`, `figure_audit`, the citation audit and reads `reporting_check` on what the project would audit and writes `.ah/external/<tool>.json`, with the sha256 of every input file taken before the run. `ah_audit external=use` (CLI `ah audit --external`; also `ah_check`) reads them as tier TX: STAT-01..05, FIG-01..04, CIT-01..06, RPT-01..03, each with a line-free key, so a finding keeps its identity when text above it moves. A result whose inputs changed, that is unreadable, or that a project requires (`external: {required: [...]}`) and never ran, is one EXT-00 (major); the tool's own findings are carried in the ledger rather than marked fixed by their absence. A re-run is recorded with cause `evidence-changed`, a result gone stale by an edit with `text-changed`, never `UNEXPLAINED`. The statistical and figure checks ship at minor (candidates for review) and are promoted in `ah.yaml` `levels:`. A numbers_audit run without SciPy fails instead of recording an empty result. New CLI: `ah external plan|status`. Engine rubric 1.3.0, `BUNDLE_REV` `dsh7`. On a copy of `paper/rsi-local`: 326 citation findings, an unchanged second audit adds 0 new, one edit gives exactly one EXT-00. `numbers_audit` now reads all prose files as one manuscript, so a total N that disagrees between Methods and Results, or a subgroup larger than the total, is found across files (per file it was missed); findings map back to their own file and line. `reporting_check` verdicts are read from `.dsh/reporting/` (never re-judged): RPT-01 not reported or partial (minor), RPT-02 a recorded quote is gone (major), RPT-03 not assessed or an absence claim older than the latest edit (info); recording a verdict or editing the manuscript makes the stored result stale. Phase 2 of the writing-feedback plan. See [Writing](WRITING.md#external-checks-in-the-ledger-tier-tx).

## 0.48.2

Fixes from the real-model research-cycle run through guide steps 5–8.

- **The plugin is explicitly Linux-only.** `package.json` now declares `"os": ["linux"]`, so npm and pnpm refuse installation on Windows and macOS. - **Jev source routing for `literature_search`.** With a TypeSafe key, [Jev](https://docs.typesafe.ai) chooses which domain sources (PubMed, arXiv, bioRxiv/medRxiv, INSPIRE, and ADS when keyed) to add to OpenAlex and Semantic Scholar, instead of keyword regexes. On objective labels it routes 116 of 120 PubMed-derived queries to PubMed (rules: 48), 97% of arXiv-hosted papers to arXiv (rules: 18%), and routes non-English queries (tried: Spanish, French, German, Chinese, Japanese) that the keyword rules miss entirely. It never selects keyed or explicit-only sources. See [Search](SEARCH.md#jev-source-routing) for the policy, evaluation, and its limits.
- **Hierarchy: topic search or something else.** When Jev is at least 0.9 sure a query is not a topic search (retraction, one named paper, trials, datasets, patents, grants, venue, news/regulation), only OpenAlex and Semantic Scholar are searched and the result is in hint mode (`routing.mode: "hint_only"`, with `gated_by` and `skipped`). On a pre-registered test of 95 queries this cut wasted extra-source calls on non-paper queries from 28 (independent routing) and 15 (keyword rules) to 2, without any of the 55 topic queries losing a source. On 148 queries written blind to the baseline, Jev recognised 94% of non-paper asks against 40% for a keyword baseline (non-English: 96% vs 4%). Known weaknesses: it can add a second, secondary hint (hint precision 76% vs 93%), it can add a second, secondary hint (fixed below), and venue questions are its weakest intent. A failing Jev is skipped for 60 s (10 min for a rejected key). Explicit `sources` skip routing, and `routing: "rules"` sends nothing to TypeSafe (not even for ranking).

Only tools that can run are suggested. Routing does not choose between Consensus and Parallel (they are meant to be used together) or decide when to read a URL. On human-labelled retrieval sets, with BM25 top-30 candidate pools: SciFact (300 queries) nDCG@10 0.663 to 0.757 (+0.094, 95% CI +0.065 to +0.125) and NFCorpus (300 queries) 0.314 to 0.367 (+0.053, CI +0.038 to +0.069). Phase 8 of [ScientistTwo → Academic Harness](SCIENTISTTWO-ROADMAP.md): re-execution, compliance, and method–code alignment, landed on the ledgers that already own the work — no new executor, no second gate.

- **`analysis_run action=expect` / `action=verify_scores`.** `expect` declares the reported numbers on the frozen plan: each metric carries a name, value, output path, parse format (`json`, `csv`, `tsv`, `kv`, `regex`), optional key/column/pattern, and absolute or relative tolerance, plus `reference: reported|reproduced`. It also captures the reference run's command and interpreter fingerprint. `verify_scores` reads only outputs the run itself hashed, re-hashes the file, and compares them; a changed output is `not_checked`, never judged as the run's result. It writes `runs/<id>/repro_check.json` with `"reproduction": true|false|null`; the verification event is appended to `verifications.jsonl`. A timeout, failed process, different plan version, changed entrypoint, or changed interpreter is `not_checked` with the reason (`allow_environment_drift` / `allow_entrypoint_change` override deliberately), notebook fingerprints ignore the per-run executed-notebook path, and tolerances get a `1e-9 × max(1, |expected|)` floating-point allowance so `0.25 ± 0.01` is not split by binary representation. `show`, `status`, and `export` surface the check.
- **`analysis_run action=compliance` with frozen `task_rules`.** A rule can carry a machine `check` (`equals`, `not_equals`, `greater_than`, `less_than`, `min`, `max`, `contains`, `not_contains`, `matches`, `exists`, `absent`) over a hashed output, or accept caller evidence (`{rule_id, satisfied}` or a status). The verdict is `violated` if any rule failed, `not_checked` if any rule could not be decided, and `compliant` only when all were satisfied; it writes `runs/<id>/compliance.json` and `compliance.jsonl`. A violating run is the paper's discard action: `experiment_log` excludes it from `best`, `dominance`, and grouping when a run links to it (exports keep the row with an exclusion marker, so the export remains an audit trail), and `repro_package` leaves it (and linked experiment runs) out of the package and the deposit, recording `excluded_runs` and the violated rule ids. Nothing is "refined", a non-zero exit is `not_checked`, not a violation, and a recorded violation stays sticky.
- **`repo_audit action=probe` / `action=align`.** `probe` is the cheap precursor: package/pyproject scripts, Makefile targets, top-level run/eval/benchmark scripts, Docker CMD, and fenced README commands (prose is ignored), reported as `runnable: yes|no|unknown`, `has_benchmark_entrypoint`, and `offers_re_execution: yes|maybe|no` — it executes nothing. `align` maps method anchors (`equation`, `symbol`, `constant`, `default`) to `file:line`: exactly one match is `verified`, several are `ambiguous`, none is `missing`, and each verified match yields a `bind_calls` entry `{claim, source, lines}` for `ah_claims_bind`. Scans are repository-confined, skip symlinks and oversized files, and run caller-supplied patterns in a vm with a hard time budget, so a catastrophic regex is `not_checked`, not a hung tool. It writes nothing and never edits the manuscript; a match is a location, not a semantic proof.
- **`citation action=repair`.** For each recorded metadata mismatch (`doi_not_registered`, `invalid_doi`, `title_mismatch`, `year_mismatch`, `venue_mismatch`, `first_author_mismatch`), it grounds through DOI and title resolution (Crossref, arXiv, INSPIRE, S2, paper_get), accepts only a record whose title matches the cited paper (with an exact-comparison fallback when a non-Latin title normalizes to nothing), reports whether the citation key survived sanitization, and writes a **new** `.bib` plus a `.repair.json` sidecar. The input is never modified, writes refuse symlinked targets, a title-mismatched grounding is rejected and listed, a retracted record is reported as not repairable metadata, and unresolved records are reported, never guessed. The new `.bib` is re-serialized from parsed records, so fields the exporter cannot represent may be dropped; the sidecar and docs say so. The roadmap's `HALLUCINATED`/`MISMATCH` labels are engine-side only; the plugin's audit vocabulary is `problem|review|unverified|no_issues_found`, and repair is keyed on that and its finding codes.
- **`provenance_audit action=arms` and three new unsupported states.** `arms` rebuilds the index and returns one four-column readiness roll-up over artifacts that already exist — reported vs recomputed (`analysis_run` expectations and re-executions), protocol digest (experiment variants against their baseline), references (deep-review citation verdicts), and method–code (AH claims bound to code files) — with `ready` / `partial` / `not_ready` totals and `n/a`, never a pass, where an artifact has no such column. The new states are `rerun_mismatch` (a declared value did not reproduce), `no_attribution` (an ablation reading or verdict attributes no component), and `verdict_missing` (staged runs or an ablation with no human verdict). The audit now indexes `ablation`, `repro_check`/compliance, and `deep_review extra_checks.json` (a `flagged` validity check becomes an `unverified` claim; `clear` is not a claim) — closing the Phase 2 note that said these were not joined yet.

## 0.30.0

- **Added Phase 4: risk-of-bias appraisal in the `review` ledger.** New actions `appraise`, `reconcile`, `agreement`, and `appraisal_status`; four paraphrased, versioned instruments — RoB 2 (2019, 5 domains + derived overall), ROBINS-I v1 (7 + overall), QUADAS-2 (4 domains, 7 risk-of-bias/applicability cells), and Newcastle-Ottawa (3 star-count domains). - **Reviewer-keyed, backward-compatible state.** Screening and appraisal state is derived per reviewer; reviewer-less events read as `default`, so single-reviewer ledgers derive, count, and export exactly as before. Pure v0.29 ledgers keep latest-per-key behaviour even when they stored a free-text reviewer name. Identities are typed `human:<name>` / `ai:<model>`; with a declared roster, disagreements surface as conflicts, `override` replaces only that reviewer's earlier event, and `reconcile` records a consensus or third-reviewer decision while keeping the originals. A later disagreement reopens the key. A declared roster is also the appraisal panel: every declared reviewer must judge every domain before a record counts as complete.
- **Evidence rules for appraisal.** A `low`/`high` (RoB 2, QUADAS-2) or `low`/`critical` (ROBINS-I) judgement needs a verbatim quote and location. An unresolved paper, a failed check, or an unexpected result is stored `unverified` with the reason. Signalling answers are supporting detail only — the official answer-to-judgement algorithms are not implemented. An explicit `overall` override requires a reason; derived overalls are marked derived and never stored.

More than two raters is pairwise; Fleiss' κ is not implemented. Human κ never includes AI judgements; AI-vs-human and AI-vs-AI pairs are reported separately. Caveats cover skewed marginals, small samples, rater bias, and clipped intervals.
- **RoB exports.** `export` gains `rob-table` (one row per included study; domain cells, overall basis, status; NOS total stars), `rob-summary` (counts per domain, conflict, pending), and `rob-figure` (`rob-traffic-light.svg` + `rob-summary.svg` through the new `python-helpers/rob_figure.py`, matplotlib).
