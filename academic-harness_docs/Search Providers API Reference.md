# Search Providers API Reference

## Executive Summary

Modern retrieval systems for artificial intelligence agents, Retrieval-Augmented Generation (RAG) pipelines, and scientific research harnesses span four distinct architectural paradigms: **AI-native web search and synthesis APIs**, **LLM-oriented web extraction and reader platforms**, **direct web index and SERP APIs**, and **scholarly, biomedical, patent, and citation-intelligence databases**. Across these 32 providers, the ecosystem has converged on two complementary integration surfaces: RESTful HTTP/JSON APIs for deterministic programmatic orchestration and **Model Context Protocol (MCP)** servers (increasingly hosted over **Streamable HTTP** with OAuth 2.1 or Bearer token authentication alongside local `stdio` packages) for autonomous tool invocation ([Exa Search Reference](https://exa.ai/docs/reference/search), [Parallel Search MCP](https://docs.parallel.ai/integrations/mcp/search-mcp), [Perplexity MCP Server](https://docs.perplexity.ai/docs/getting-started/integrations/mcp-server), [scite MCP Overview](https://docs.scite.ai/mcp/overview)).

Key structural shifts define the landscape as of late 2026:

- **Legacy Search API Consolidation and Cloud Grounding**: Microsoft retired the standalone Bing Search APIs on August 11, 2025, migrating enterprise customers to **Grounding with Bing Search** inside Azure AI Foundry at $14.00 per 1,000 transactions ([Microsoft Lifecycle Notice](https://learn.microsoft.com/en-us/lifecycle/announcements/bing-search-api-retirement), [Microsoft Grounding with Bing](https://www.microsoft.com/en-us/bing/apis)). Google closed the **Custom Search JSON API** ($5.00 per 1,000 queries, capped at 10,000 queries/day) to new customers and scheduled its discontinuation for January 1, 2027, directing workloads to **Vertex AI Agent Search** ($1.50 to $4.00 per 1,000 queries) and **Grounded Generation with Google Search** ($35.00 per 1,000 requests) ([Google Custom Search Overview](https://developers.google.com/custom-search/v1/overview), [Vertex AI Search Pricing](https://cloud.google.com/generative-ai-app-builder/pricing?authuser=1)).
- **Tiered Latency vs. Synthesis Depth in AI Search**: AI-native search providers expose explicit latency-versus-depth controls. **Parallel Web Systems** offers `turbo` (~200 ms p50) and `fast` (~700 ms) modes at $1.00 per 1,000 requests alongside `basic`/`advanced` modes at $5.00 per 1,000 requests ([Parallel Search Quickstart](https://docs.parallel.ai/search/search-quickstart), [Parallel Pricing](https://docs.parallel.ai/getting-started/pricing.md)). **Exa** differentiates cached `lite` search ($4.00/1K), balanced `auto` search ($7.00/1K), and multi-step `deep`/`deep-lite` synthesis ($12.00/1K) ([Exa Search Reference](https://exa.ai/docs/reference/search), [Exa Pricing](https://exa.ai/docs/admin/pricing)). **Perplexity** pairs its raw **Search API** ($5.00/1K standard, $1.00/1K fast) with multi-model **Agent API** and **Sonar** grounded reasoning endpoints ([Perplexity Pricing](https://docs.perplexity.ai/docs/getting-started/pricing), [Perplexity Search Quickstart](https://docs.perplexity.ai/docs/search/quickstart.md)).
- **First-Party Academic MCP Proliferation**: Scientific literature platforms that previously operated only as web applications or closed REST services now maintain official hosted Streamable HTTP MCP servers, including **Consensus** (`https://mcp.consensus.app/mcp`), **scite** (`https://api.scite.ai/mcp` with 25 tools across literature, regulatory evidence, and collections), and **Elicit** (`https://elicit.com/api/mcp` alongside REST API v2 at `https://elicit.com/api/v2`) ([Consensus MCP Docs](https://docs.consensus.app/docs/mcp), [scite MCP Overview](https://docs.scite.ai/mcp/overview), [Elicit API Reference](https://docs.elicit.com/llms.txt)). Meanwhile, open bibliographic backbones led by **OpenAlex** (300M+ core works, CC0 license) and **Semantic Scholar** (214M papers, 2.49B citations, SPECTER2 embeddings) anchor high-volume metadata discovery and graph traversal ([OpenAlex API Reference](https://help.openalex.org/api/), [Semantic Scholar API](https://www.semanticscholar.org/product/api)).

## AI-Native Web Search Providers

AI-native web search APIs replace raw ten-blue-link SERP retrieval with pre-chunked, relevance-scored passages, optional multi-hop query expansion, and structured JSON output tailored for LLM context windows.

### Tavily

- **API Architecture and Authentication**: Tavily serves REST requests from `https://api.tavily.com` using JSON POST bodies authenticated via `Authorization: Bearer tvly-YOUR_API_KEY` ([Tavily Intro](https://docs.tavily.com/documentation/api-reference/introduction), [Tavily Search Reference](https://docs.tavily.com/documentation/api-reference/endpoint/search)). Optional attribution headers include `X-Project-ID` for project-level tracking, `X-Session-Id` for grouping multi-turn agent calls, and `X-Human-Id` (hashed prior to storage) for end-user analytics ([Tavily Intro](https://docs.tavily.com/documentation/api-reference/introduction)).
- **Core Endpoints and Parameters**:
  - `POST https://api.tavily.com/search`: Requires `query` (string). Key parameters include `search_depth` (`ultra-fast`, `fast`, `basic` [default], or `advanced`), `chunks_per_source` (integer `1`–`3`, default `3`, supported on `basic`, `fast`, and `advanced`), `max_results` (`0`–`20`, default `10`), `topic` (`general`, `news`, or `finance`), `time_range` (`day`, `week`, `month`, `year`), `start_date`/`end_date` (`YYYY-MM-DD`), `include_domains` (up to 300 domains), `exclude_domains` (up to 150 domains), `include_domains_mode` (`restrict` or `prefer`), `include_answer` (`false`, `true`/`basic`, or `advanced`), `include_raw_content` (`false`, `markdown`, or `text`), `country`, `language`, and `auto_parameters` ([Tavily Search Reference](https://docs.tavily.com/documentation/api-reference/endpoint/search)).
  - Additional endpoints include `POST /extract` (URL content extraction), `POST /crawl` (site-wide traversal), `POST /map` (site graph mapping), and `POST /research` (comprehensive multi-step research) ([Tavily Intro](https://docs.tavily.com/documentation/api-reference/introduction)).
- **MCP Integration**: Tavily provides both a local stdio package (`npx -y tavily-mcp@latest`, requiring Node.js v20+) and a remote MCP server at `https://mcp.tavily.com/mcp` supporting OAuth or `?tavilyApiKey=<key>` ([Tavily MCP Repo](https://github.com/tavily-ai/tavily-mcp)). Exposed tools include `tavily-search`, `tavily-extract`, and website mapping/traversal tools ([Tavily MCP Repo](https://github.com/tavily-ai/tavily-mcp)). Tavily also hosts a separate documentation-only MCP server (`search_tavily_docs`, `query_docs_filesystem_tavily_docs`) ([Tavily Docs MCP](https://docs.tavily.com/mcp)).
- **Pricing and Rate Limits**: `basic`, `fast`, and `ultra-fast` searches consume 1 API credit; `advanced` search and `auto_parameters: true` each consume 2 credits ([Tavily Credits](https://docs.tavily.com/documentation/api-credits)). Plans include **Researcher** (Free, 1,000 credits/month), **Project** ($30/month for 4,000 credits, $0.0075/credit), **Bootstrap** ($100/month for 15,000 credits, $0.0067/credit), **Startup** ($220/month for 38,000 credits, $0.0058/credit), **Growth** ($500/month for 100,000 credits, $0.005/credit), and Pay-As-You-Go ($0.008/credit) ([Tavily Credits](https://docs.tavily.com/documentation/api-credits)).
- **Pros and Cons**:
  - **Pros**: Configurable latency-relevance spectrum (`ultra-fast` through `advanced`); granular chunk-per-source controls (`1`–`3` chunks) that prevent context bloat; built-in `finance` and `news` topic modes; dual remote OAuth and local `npx` MCP support ([Tavily Search Reference](https://docs.tavily.com/documentation/api-reference/endpoint/search), [Tavily MCP Repo](https://github.com/tavily-ai/tavily-mcp)).
  - **Cons**: Enabling `auto_parameters` or `advanced` depth doubles credit consumption to 2 credits per request; `chunks_per_source` is unavailable in `ultra-fast` mode; `filter_by_published_date` discards pages where Tavily's beta date parser cannot detect a date ([Tavily Search Reference](https://docs.tavily.com/documentation/api-reference/endpoint/search), [Tavily Credits](https://docs.tavily.com/documentation/api-credits)).

### Exa

- **API Architecture and Authentication**: Exa operates at `https://api.exa.ai` using `Authorization: Bearer $EXA_API_KEY` or `x-api-key: $EXA_API_KEY`, with official Python (`exa-py`) and TypeScript (`exa-js`) SDKs ([Exa Search Reference](https://exa.ai/docs/reference/search)). Unauthenticated calls to x402-enabled endpoints can also receive an HTTP 402 payment challenge ([Exa Search Reference](https://exa.ai/docs/reference/search)).
- **Core Endpoints and Parameters**:
  - `POST https://api.exa.ai/search`: Accepts `query` (required), `type` (`auto` [default], `lite` [cached low-latency], `deep-lite` [~4s synthesis], or `deep` [multi-step research]; legacy `instant`, `fast`, and `deep-reasoning` map to `lite`, `lite`, and `deep`), `numResults` (`1`–`100` public, up to `1,000` Enterprise), `includeDomains`/`excludeDomains` (up to 1,200 hostnames, path prefixes, or wildcards each), `startPublishedDate`/`endPublishedDate` (ISO 8601), `category` (`company`, `publication`, `news`, `personal site`, `financial report`, `people`), `contents` (`highlights`, `text`, summaries, `snapshotAsOf`), and `outputSchema` (JSON Schema for structured synthesis, supporting SSE streaming via `stream: true`) ([Exa Search Reference](https://exa.ai/docs/reference/search), [Exa Pricing](https://exa.ai/docs/admin/pricing)).
  - Additional endpoints include `/contents`, `/answer`, and `/monitors` ([Exa Pricing](https://exa.ai/docs/admin/pricing)).
- **MCP Integration**: Exa's official Streamable HTTP MCP server runs at `https://mcp.exa.ai/mcp` (repository `exa-labs/exa-mcp-server`) and supports anonymous rate-limited use, OAuth (`/mcp?login`), or API key headers/query params ([Exa MCP Repo](https://github.com/exa-labs/exa-mcp-server)). Default tools are `web_search_exa` and `web_fetch_exa`, while optional tools `web_search_advanced_exa` and `agent_run` are enabled via `?tools=web_search_exa,web_fetch_exa,web_search_advanced_exa,agent_run` ([Exa MCP Repo](https://github.com/exa-labs/exa-mcp-server)).
- **Pricing and Rate Limits**: Free tier provides $10 in credits resetting on the first of every month (up to 2,500 `lite` searches) plus a $10 one-time onboarding bonus ([Exa Pricing](https://exa.ai/docs/admin/pricing)). Per 1,000 requests (up to 10 results): `lite`/`instant` costs $4.00, `auto`/`fast` costs $7.00, and `deep-lite`/`deep` costs $12.00 (legacy `deep-reasoning` $15.00), with each result above 10 billed at $1.00 per 1,000 results ([Exa Pricing](https://exa.ai/docs/admin/pricing)). `/contents` costs $1.00 per 1,000 pages per content type; AI summaries add $1.00 per 1,000 pages; `/answer` is $5.00 per 1,000 requests ([Exa Pricing](https://exa.ai/docs/admin/pricing)).
- **Pros and Cons**:
  - **Pros**: Neural/semantic retrieval excels at entity discovery (`people`, `company`, `publication`, `financial report`); path-prefix and wildcard domain filtering up to 1,200 entries; native `outputSchema` structured synthesis; generous $10/month recurring free credit ([Exa Search Reference](https://exa.ai/docs/reference/search), [Exa Pricing](https://exa.ai/docs/admin/pricing)).
  - **Cons**: `lite` mode serves cached index snapshots only and never fetches live pages; `people` and `company` categories reject publication-date filters; `outputSchema` is restricted to at most 10 total properties and 2 levels of object nesting and adds ~2 seconds of synthesis latency ([Exa Search Reference](https://exa.ai/docs/reference/search)).

### Perplexity

- **API Architecture and Authentication**: Perplexity exposes its API platform at `https://api.perplexity.ai` using `Authorization: Bearer $PERPLEXITY_API_KEY`, supported by official Python (`perplexityai`) and TypeScript (`@perplexity-ai/perplexity_ai`) SDKs ([Perplexity Search Quickstart](https://docs.perplexity.ai/docs/search/quickstart.md), [Perplexity Agent Quickstart](https://docs.perplexity.ai/docs/agent-api/quickstart.md)).
- **Core Endpoints and Parameters**:
  - **Search API** (`POST https://api.perplexity.ai/search`): Returns raw ranked web results (`title`, `url`, `snippet`, `date`, `last_updated`) without LLM generation. Parameters include `query`, `max_results` (`1`–`20`, default `10`), `country` (ISO 3166-1 alpha-2), domain/language filters, and `search_type: "fast"` for low-latency/low-cost retrieval ([Perplexity Search Quickstart](https://docs.perplexity.ai/docs/search/quickstart.md)).
  - **Agent API** (`POST https://api.perplexity.ai/v1/agent` or OpenAI-compatible `POST /v1/responses`): Multi-provider agentic interface supporting third-party and Perplexity models (`anthropic/claude-sonnet-5-5`, `openai/gpt-6-sol`, `google/gemini-4-argon`, `xai/grok-4.7`, `perplexity/sonar`) with built-in tools (`web_search`, `fetch_url`, `image_search`, `people_search`, `finance_search`) and presets (`fast`, `medium`, `high`, `low`) ([Perplexity Pricing](https://docs.perplexity.ai/docs/getting-started/pricing), [Perplexity Agent Quickstart](https://docs.perplexity.ai/docs/agent-api/quickstart.md)).
  - **Sonar API, Embeddings API, and Decisions API**: Sonar models (`Sonar`, `Sonar Pro`, `Sonar Reasoning Pro`, `Sonar Deep Research`) provide grounded synthesis; Embeddings (`pplx-embed-v1-0.6b`/`4b` and `pplx-embed-context-v1-0.6b`/`4b`) and Decisions (`pplx-decider-v1.2`) handle vectorization and probabilistic routing ([Perplexity Pricing](https://docs.perplexity.ai/docs/getting-started/pricing), [Perplexity Docs Index](https://docs.perplexity.ai/llms.txt)).

### Firecrawl

- **API Architecture and Authentication**: Firecrawl's v2 REST API is hosted at `https://api.firecrawl.dev/v2` and authenticates with `Authorization: Bearer $FIRECRAWL_API_KEY` (with limited keyless trial support) ([Firecrawl Intro](https://docs.firecrawl.dev/introduction)). ### OpenAlex

- **API Architecture and Authentication**: Maintained by OurResearch, OpenAlex (`https://api.openalex.org`) indexes 300M+ curated core scholarly works (and ~60% more via the opt-in `corpus=all` parameter) under a **CC0 public-domain license** ([OpenAlex API Reference](https://help.openalex.org/api/)). While basic keyless requests work immediately, supplying a free verified API key via `?api_key=YOUR_KEY` or `Authorization: Bearer YOUR_KEY` raises the daily budget 10x (to $1.00/day free budget) and unlocks cursor pagination beyond the first page ([OpenAlex Auth Docs](https://help.openalex.org/api/authentication.md)). Keys can even be provisioned programmatically via `POST https://api.openalex.org/api-keys` with `{"email": "user@example.org"}` ([OpenAlex Auth Docs](https://help.openalex.org/api/authentication.md)).
- **Core Endpoints and Parameters**:
  - Entity endpoints: `/works`, `/authors`, `/sources`, `/institutions`, `/topics`, `/publishers`, `/funders`, plus `/rate-limit` ([OpenAlex API Reference](https://help.openalex.org/api/), [OpenAlex Auth Docs](https://help.openalex.org/api/authentication.md)).
  - Query parameters: `filter` (supports up to 100 OR values, e.g., `publication_year:2024,is_oa:true`), `search` (full-text search), `sort`, `group_by` (faceted aggregations), `select` (field projection), `sample` (up to 10,000 random records), `per_page` (`1`–`100`, default `25`), `page` (up to 10,000 results), and `cursor` (unlimited deep paging with an API key) ([OpenAlex API Reference](https://help.openalex.org/api/), [OpenAlex Auth Docs](https://help.openalex.org/api/authentication.md)).
  - Every response returns `meta` (`count`, `page`, `per_page`, `cost_usd`) and rate-limit headers (`X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Credits-Used`, `X-RateLimit-Reset`) ([OpenAlex API Reference](https://help.openalex.org/api/), [OpenAlex Auth Docs](https://help.openalex.org/api/authentication.md)).
- **MCP Integration**: Standalone Python MCP server `DeyangLiu123/openalex-mcp` (`uvx --from git+https://github.com/DeyangLiu123/openalex-mcp.git openalex-mcp`) exposes 9 tools: `search_works`, `get_work`, `get_citing_works`, `get_references`, `search_authors`, `resolve_entity`, `harvest_candidates`, `get_api_quota`, and `download_work_pdf` (with atomic write and 200 MiB boundary checks) ([DeyangLiu123 openalex-mcp](https://github.com/DeyangLiu123/openalex-mcp)).
- **Pricing and Rate Limits**:
  - Throughput: **10 RPS** without a key, **30 RPS** with a free or prepaid API key, and **50 RPS** on an annual plan ([OpenAlex Auth Docs](https://help.openalex.org/api/authentication.md)). Semantic search is capped at **1 RPS**, and complex Boolean queries (>5 `OR`/`AND`/`NOT` operators) are capped at 1 RPS (no key), 5 RPS (free key), and 25 RPS (annual) ([OpenAlex Auth Docs](https://help.openalex.org/api/authentication.md)).
  - Cost accounting against the free $1.00/day budget (and pay-as-you-go beyond it): singleton ID lookups are free, filtered list queries cost ~$0.0001 (`meta.cost_usd`), search queries cost ~$0.001, and content downloads from `content.openalex.org` cost ~$0.01 ([OpenAlex API Reference](https://help.openalex.org/api/), [DeyangLiu123 openalex-mcp](https://github.com/DeyangLiu123/openalex-mcp)).
- **Pros and Cons**:
  - **Pros**: Largest open CC0 scholarly graph (300M+ core works); fast 30 RPS throughput on a free API key; rich entity resolution across DOIs, ORCIDs, RORs, and ISSNs; transparent per-call `meta.cost_usd` reporting ([OpenAlex API Reference](https://help.openalex.org/api/), [OpenAlex Auth Docs](https://help.openalex.org/api/authentication.md)).
  - **Cons**: Nested entities in work records are dehydrated stubs requiring secondary lookups for full metadata; OpenAlex deprecated `filter=field.search:` in favor of top-level `search=`, which searches full text and can lower precision unless paired with topic/venue filters ([OpenAlex API Reference](https://help.openalex.org/api/), [DeyangLiu123 openalex-mcp](https://github.com/DeyangLiu123/openalex-mcp)).

### Semantic Scholar

- **API Architecture and Authentication**: Operated by the Allen Institute for AI (Ai2), Semantic Scholar indexes 214 million papers, 2.49 billion citations, and 79 million authors ([Semantic Scholar API](https://www.semanticscholar.org/product/api)). Base URL is `https://api.semanticscholar.org/graph/v1` (plus `/recommendations/v1` and `/datasets/v1`), authenticated via the `x-api-key` HTTP header ([Semantic Scholar Usage](https://semanticscholar.readthedocs.io/en/latest/usage.html)).
- **Core Endpoints and Parameters**:
  - **Academic Graph Service**: Relevance paper search (`/paper/search`), bulk boolean paper search (`/paper/search/bulk` retrieving up to 1,000 records per call and 10,000,000 total sorted by `paperId`, `publicationDate`, or `citationCount`), exact title match (`match_title`), batch paper/author lookup (`POST /graph/v1/paper/batch` for up to 1,000 IDs using CorpusId, DOI, arXiv, MAG, ACL, or PMID), citation/reference traversal, author search, autocomplete, and **snippet search** (`search_snippet` returning ~500-word excerpts from title, abstract, or body text) ([Semantic Scholar Usage](https://semanticscholar.readthedocs.io/en/latest/usage.html)).
  - Search filters include `year` (e.g., `2020-2026`), `publication_date_or_year`, `publication_type`, `open_access_pdf`, `venue`, `fields_of_study`, `min_citation_count`, and `fields` (including `embedding.specter_v2` and `tldr`) ([Semantic Scholar API](https://www.semanticscholar.org/product/api), [Semantic Scholar Usage](https://semanticscholar.readthedocs.io/en/latest/usage.html)).
  - **Recommendations & Datasets Services**: Single-paper or positive/negative seed-list paper recommendations (`get_recommended_papers_from_lists`), plus full corpus snapshots and incremental diffs ([Semantic Scholar Usage](https://semanticscholar.readthedocs.io/en/latest/usage.html)).
- **MCP Integration**: Community FastMCP server `dosigner/semantic-scholar-mcp-merged` (`uv run semantic-scholar-mcp-merged`) provides **24 tools** spanning relevance/bulk/title/snippet paper search, batch paper/author lookups, citation/reference graphs, positive/negative paper recommendations, automatic session paper tracking with enriched BibTeX export (`export_bibtex`), and author deduplication ([Semantic Scholar MCP Repo](https://github.com/dosigner/semantic-scholar-mcp-merged/blob/main/README.md)).
- **Pricing and Rate Limits**: 100% free API and open datasets ([Semantic Scholar API](https://www.semanticscholar.org/product/api)). Unauthenticated callers share a global pool of 1,000 RPS (subject to heavy-load throttling), while introductory authenticated API keys receive a dedicated **1 RPS** across endpoints (with higher limits granted upon application) ([Semantic Scholar API](https://www.semanticscholar.org/product/api)).
- **Pros and Cons**:
  - **Pros**: Native **SPECTER2** paper embeddings, AI-generated **TLDR** summaries, influential-citation flags, positive/negative seed recommendations, and ~500-word full-text `snippet_search`—all completely free ([Semantic Scholar API](https://www.semanticscholar.org/product/api), [Semantic Scholar Usage](https://semanticscholar.readthedocs.io/en/latest/usage.html)).
  - **Cons**: Introductory authenticated rate limit is strictly 1 RPS, requiring careful client-side throttling and exponential backoff (`Retry-After`) in multi-agent swarms ([Semantic Scholar API](https://www.semanticscholar.org/product/api), [Semantic Scholar Usage](https://semanticscholar.readthedocs.io/en/latest/usage.html)).

Sequential searches are rate-limited to **1 query/second** ([Consensus MCP Docs](https://docs.consensus.app/docs/mcp)).
- **Pros and Cons**:
  - **Pros**: Unmatched study-design filtering (`rct`, `meta-analysis`, `sample_size_min`, `sjr_max` journal quartile, `human`, `medical_mode`) directly inside MCP tool parameters; works immediately in Claude Code, Cursor, Codex, and Claude Desktop ([Consensus MCP Docs](https://docs.consensus.app/docs/mcp)).

Usage draws from a monthly plan allowance resetting on the 1st of each month (returning JSON-RPC error `-32001` when exhausted or `-32003`/`-32042` when an entitlement upgrade is required) ([scite MCP Overview](https://docs.scite.ai/mcp/overview)).

  - **Cons**: No free permanent tier for MCP/API (requires Premium/Pro subscription); `GET /mcp` and server-initiated SSE streams are unsupported (returns HTTP 405; must use `POST /mcp`) ([scite MCP Overview](https://docs.scite.ai/mcp/overview)).

### arXiv API

Parameters are `search_query` (fielded prefixes `ti:`, `au:`, `abs:`, `cat:`, `co:`, `jr:`, `rn:`, `id:`, `all:` combined with `AND`, `OR`, `ANDNOT`), `id_list` (comma-delimited arXiv IDs), `start` (0-based), `max_results` (up to 2,000 per slice, max 30,000 total), `sortBy` (`relevance`, `lastUpdatedDate`, `submittedDate`), and `sortOrder` (`ascending`, `descending`) ([arXiv API Manual](https://info.arxiv.org/help/api/user-manual.html)).
- **MCP Integration**:
  - `@cyanheads/arxiv-mcp-server` (`npx -y @cyanheads/arxiv-mcp-server@latest` or public hosted `https://arxiv.caseyjhand.com/mcp`): Exposes `arxiv_search`, `arxiv_get_metadata` (batch up to 10 IDs), `arxiv_read_paper` (cascades through native arXiv HTML -> ar5iv HTML -> PDF text extraction), and `arxiv_list_categories`, plus an optional local SQLite + FTS5 OAI-PMH mirror ([arXiv MCP Server](https://github.com/cyanheads/arxiv-mcp-server/blob/main/README.md)).
  - `blazickjp/arxiv-mcp-server`: Python MCP server exposing `search_papers` with `abstract_mode` (`none`, `snippet`, `full`) and automatic rate-limit backoff ([blazickjp arXiv MCP](https://github.com/blazickjp/arxiv-mcp-server/blob/main/src/arxiv_mcp_server/tools/search.py)).
- **Pricing and Rate Limits**: 100% free (CC0 1.0 metadata), but arXiv's Terms of Use strictly enforce **at most 1 request every 3 seconds (0.33 RPS)** and **a single concurrent connection** across all machines controlled by a user ([arXiv API Terms](https://info.arxiv.org/help/api/tou.html)).
- **Pros and Cons**:
  - **Pros**: Primary source of truth for preprints in physics, mathematics, computer science, quantitative biology, and statistics; HTML/ar5iv full-text extraction via `@cyanheads/arxiv-mcp-server` preserves LaTeX equations far better than raw PDF parsing ([arXiv API Manual](https://info.arxiv.org/help/api/user-manual.html), [arXiv MCP Server](https://github.com/cyanheads/arxiv-mcp-server/blob/main/README.md)).
  - **Cons**: Strict 1-request-per-3-seconds rate limit; Atom XML responses require XML namespace parsing; new submissions only appear in the API after midnight following processing ([arXiv API Manual](https://info.arxiv.org/help/api/user-manual.html), [arXiv API Terms](https://info.arxiv.org/help/api/tou.html)).

### PubMed and Europe PMC

- **NCBI Entrez E-utilities (`https://eutils.ncbi.nlm.nih.gov/entrez/eutils/`)**:
  - Provides 9 server-side CGI endpoints across 38 biomedical databases (including PubMed's 35M+ citations and PMC): `einfo.fcgi` (database schema), `esearch.fcgi` (`db`, `term`, `usehistory=y` returning `WebEnv` and `query_key`), `epost.fcgi` (UID upload), `esummary.fcgi` (document summaries), `efetch.fcgi` (`rettype`, `retmode` for full records/XML), `elink.fcgi` (cross-database and citation links), `egquery.fcgi`, `espell.fcgi`, and `ecitmatch.cgi` (batch citation string to PMID matching) ([NCBI E-utilities Intro](https://www.ncbi.nlm.nih.gov/books/NBK25497/)).
  - **Rate Limits**: **3 requests/second** without an API key; **10 requests/second** with a free NCBI API key (`api_key` parameter, accompanied by registered `tool` and `email` parameters); enhanced keys >10 RPS available via application to `info@ncbi.nlm.nih.gov` ([NCBI E-utilities Intro](https://www.ncbi.nlm.nih.gov/books/NBK25497/), [NCBI Enhanced Key FAQ](https://support.nlm.nih.gov/knowledgebase/article/KA-05318/en-us)). Large bulk jobs must run on weekends or between 9:00 PM and 5:00 AM US Eastern Time ([NCBI E-utilities Intro](https://www.ncbi.nlm.nih.gov/books/NBK25497/)).
- **Europe PMC RESTful API (`https://www.ebi.ac.uk/europepmc/webservices/rest/`)**:
  - Indexes 33M+ publications, 10.2M full-text articles, and 6.5M open-access articles with text-mined biological annotations (genes/proteins, chemicals, diseases, GO terms, organisms) ([Europe PMC REST API](https://europepmc.org/RestfulWebService)).
  - `GET /search?query={query}` supports `resulttype` (`idlist`, `lite`, `core`), `format` (`xml`, `json`, `dc`), and sorting (`sort_cited:y`, `sort_date:y`) without requiring an API key ([Europe PMC REST API](https://europepmc.org/RestfulWebService)).
- **MCP Integration**: Community servers include `openpharma-org/pubmed-mcp` (`pubmed_articles` with `search_keywords`, `search_advanced`, `get_article_metadata`, `get_article_pdf`), `grll/pubmedmcp`, and `@ncukondo/mcp-server-pubmed` (`search`, `fetch_summary`, `get_full_text`) ([openpharma pubmed-mcp](https://github.com/openpharma-org/pubmed-mcp), [grll pubmedmcp](https://github.com/grll/pubmedmcp), [ncukondo mcp-server-pubmed](https://github.com/ncukondo/mcp-server-pubmed)).
- **Pros and Cons**:
  - **Pros**: Authoritative MeSH-indexed biomedical literature; Entrez History Server (`WebEnv`/`query_key`) chains multi-step pipelines server-side; Europe PMC adds text-mined entity annotations and direct JSON responses ([NCBI E-utilities Intro](https://www.ncbi.nlm.nih.gov/books/NBK25497/), [Europe PMC REST API](https://europepmc.org/RestfulWebService)).
  - **Cons**: NCBI E-utilities require two-step (`esearch` -> `esummary`/`efetch`) orchestration and enforce IP blocks if the 3 RPS / 10 RPS ceiling is violated ([NCBI E-utilities Intro](https://www.ncbi.nlm.nih.gov/books/NBK25497/)).

### Crossref and Unpaywall

- **Crossref REST API (`https://api.crossref.org/v1/`)**:
  - Official DOI registration metadata catalog (~180 million records, ~1 billion API hits/month) ([Crossref Access Docs](https://www.crossref.org/documentation/retrieve-metadata/rest-api/access-and-authentication/), [Crossref Rate Limits Blog](https://www.crossref.org/blog/announcing-changes-to-rest-api-rate-limits/)). Endpoints include `GET /v1/works/{doi}`, `GET /v1/works?query.bibliographic=...&filter=...`, `GET /v1/journals/{issn}`, and `GET /v1/members/{member_id}/works` ([Crossref Access Docs](https://www.crossref.org/documentation/retrieve-metadata/rest-api/access-and-authentication/)).
  - **Rate Limits (Effective Dec 1, 2025)**: Differentiated by pool and request type ([Crossref Rate Limits Blog](https://www.crossref.org/blog/announcing-changes-to-rest-api-rate-limits/)):
    - **Public Pool** (no `mailto`): **5 RPS** on single-DOI lookups (`concurrency: 1`) and **1 RPS** on list/search queries (`concurrency: 1`).
    - **Polite Pool** (free; append `?mailto=you@example.com`): **10 RPS** on single-DOI lookups (`concurrency: 3`) and **3 RPS** on list/search queries (`concurrency: 3`).
    - **Metadata Plus Pool** (paid subscription with `Crossref-Plus-API-Token: Bearer <key>`): **150 RPS** with no concurrency cap ([Crossref Access Docs](https://www.crossref.org/documentation/retrieve-metadata/rest-api/access-and-authentication/), [Crossref Rate Limits Blog](https://www.crossref.org/blog/announcing-changes-to-rest-api-rate-limits/)).
- **Unpaywall REST API (`https://api.unpaywall.org/v2/{doi}?email=YOUR_EMAIL`)**:
  - Resolves any DOI to its legal Open Access status and direct full-text PDF URLs (`best_oa_location`, `oa_locations`), free up to **100,000 calls per day** ([Unpaywall API](https://unpaywall.org/products/api)).
  - **Important Deprecation**: Unpaywall retired its `GET /v2/search` endpoint on **September 18, 2026** (now returning `HTTP 410 Gone`), directing all text-search queries to `https://api.openalex.org/works?search=...` ([Unpaywall API](https://unpaywall.org/products/api)).
- **Pros and Cons**:
  - **Pros**: Crossref is the canonical source of truth for DOI metadata, funding data, and license URLs; Unpaywall (`GET /v2/{doi}`) is the simplest free resolver for open-access PDF links (100K/day) ([Crossref Access Docs](https://www.crossref.org/documentation/retrieve-metadata/rest-api/access-and-authentication/), [Unpaywall API](https://unpaywall.org/products/api)).
  - **Cons**: Crossref list/search queries were tightened to 3 RPS (Polite) and 1 RPS (Public) in December 2025; Unpaywall's `/v2/search` endpoint is permanently retired (`410 Gone`) ([Crossref Rate Limits Blog](https://www.crossref.org/blog/announcing-changes-to-rest-api-rate-limits/), [Unpaywall API](https://unpaywall.org/products/api)).

### CORE

- **API Architecture and Authentication**: CORE aggregates open-access research across 15,000+ institutional and subject repositories, reporting 452M+ searchable records and 57M+ hosted full texts ([CORE API Services](https://core.ac.uk/services/api)). Its v3 REST API (`https://api.core.ac.uk/v3`) uses `Authorization: Bearer $CORE_API_KEY` ([CORE API Guide](https://github.com/wentorai/research-plugins/blob/main/skills/literature/fulltext/core-api-guide/SKILL.md)).
- **Core Endpoints and Rate Limits**:
  - `GET /v3/search/works?q={query}&limit={n}&offset={n}` (returns metadata plus inline `fullText` string when available), `GET /v3/works/{core_id_or_doi}`, `POST /v3/works` (batch lookup), and `GET /v3/data-providers` ([CORE API Guide](https://github.com/wentorai/research-plugins/blob/main/skills/literature/fulltext/core-api-guide/SKILL.md)).
  - Unregistered access is capped at **1 batch request or 5 single requests per 10 seconds (0.5 RPS)**; registered academic keys allow ~150 requests per 15-minute window (10 RPM), with higher limits for Supporting/Sustaining Members ([CORE API Services](https://core.ac.uk/services/api), [CORE API Guide](https://github.com/wentorai/research-plugins/blob/main/skills/literature/fulltext/core-api-guide/SKILL.md)).
- **Pros and Cons**:
  - **Pros**: Returns pre-extracted `fullText` directly inside the JSON work record for millions of repository papers without requiring separate PDF downloading and parsing ([CORE API Services](https://core.ac.uk/services/api), [CORE API Guide](https://github.com/wentorai/research-plugins/blob/main/skills/literature/fulltext/core-api-guide/SKILL.md)).
  - **Cons**: Tight free rate limits (0.5 RPS unregistered / 10 RPM registered academic); repository metadata quality varies across the 15,000+ upstream providers ([CORE API Services](https://core.ac.uk/services/api), [CORE API Guide](https://github.com/wentorai/research-plugins/blob/main/skills/literature/fulltext/core-api-guide/SKILL.md)).

### The Lens and Dimensions

- **The Lens (`https://api.lens.org`)**:
  - Links global patent records (120+ searchable fields on the MetaRecord architecture) with scholarly literature (`POST/GET /patent/search`, `GET /patent/{lens_id}`, `POST/GET /scholarly/search`, `POST/GET /collections/{collection_id}`), authenticating via `Authorization: Bearer <token>` or `?token=` ([Lens API Knowledge Base](https://support.lens.org/knowledge-base/lens-patent-and-scholar-api/), [Lens APIs Overview](https://about.lens.org/lens-apis/)).
  - Access requires manual approval: academic trial tokens last 14 days, while institutional/commercial use requires a Member | Custom Access contract (up to 5 tokens per user, 1-year token expiry) ([Lens API Knowledge Base](https://support.lens.org/knowledge-base/lens-patent-and-scholar-api/), [Lens APIs Overview](https://about.lens.org/lens-apis/)).
- **Dimensions (`https://app.dimensions.ai/api/dsl/v2`)**:
  - Uses a two-step authentication flow (`POST /api/auth` with `{"key": "..."}` -> 2-hour JWT used as `Authorization: JWT <token>`) to execute queries in the **Dimensions Search Language (DSL v2)** across linked publications, grants, patents, clinical trials, datasets, and policy documents ([Dimensions DSL API](https://docs.dimensions.ai/dsl/api.html)).
  - Enforces a rate limit of **30 requests per minute per IP address (0.5 RPS)** and documents an official **Dimensions Analytics MCP** server for natural-language schema exploration and scientometric aggregation ([Dimensions DSL API](https://docs.dimensions.ai/dsl/api.html)).
- **Pros and Cons**:
  - **Pros**: Unrivaled cross-domain linkage connecting scholarly papers directly to citing patents, funded grant awards, and clinical trials ([Lens APIs Overview](https://about.lens.org/lens-apis/), [Dimensions DSL API](https://docs.dimensions.ai/dsl/api.html)).
  - **Cons**: High barrier to entry (manual approval or institutional licensing required; no permanent self-serve free tier) and conservative rate limits (30 RPM on Dimensions) ([Lens APIs Overview](https://about.lens.org/lens-apis/), [Dimensions DSL API](https://docs.dimensions.ai/dsl/api.html)).

## Architecture and Selection Guide

### MCP Transport and Auth Patterns

Across the 32 providers, MCP adoption has evolved from local Node.js/Python `stdio` wrappers toward **remote Streamable HTTP** (`https://.../mcp`) endpoints:

1. **Remote Streamable HTTP with OAuth 2.1 or Bearer Auth**: Hosted directly by the provider with zero local runtime dependencies. Supported by **Exa** (`https://mcp.exa.ai/mcp`), **Perplexity** (`https://api.perplexity.ai/mcp`), **Parallel** (`https://search.parallel.ai/mcp` and `https://task-mcp.parallel.ai/mcp`), **Tavily** (`https://mcp.tavily.com/mcp`), **Firecrawl** (`https://mcp.firecrawl.dev/v2/mcp`), **Jina AI** (`https://mcp.jina.ai/v1`), **You.com** (`https://api.you.com/mcp`), **Linkup** (`https://mcp.linkup.so/mcp`), **Valyu** (`https://mcp.valyu.ai/mcp`), **Kagi** (`https://mcp.kagi.com/mcp`), **Spider** (`https://mcp.spider.cloud/mcp`), **Olostep** (`https://mcp.olostep.com/mcp`), **Bright Data** (`https://mcp.brightdata.com/mcp`), **SerpApi** (`https://mcp.serpapi.com/mcp`), **Consensus** (`https://mcp.consensus.app/mcp`), **scite** (`https://api.scite.ai/mcp`), and **Elicit** (`https://elicit.com/api/mcp`) ([Exa MCP Repo](https://github.com/exa-labs/exa-mcp-server), [Perplexity MCP Server](https://docs.perplexity.ai/docs/getting-started/integrations/mcp-server), [Parallel Search MCP](https://docs.parallel.ai/integrations/mcp/search-mcp), [Consensus MCP Docs](https://docs.consensus.app/docs/mcp), [scite MCP Overview](https://docs.scite.ai/mcp/overview), [Elicit API Reference](https://docs.elicit.com/llms.txt)).
2. **Context-Window Token Guardrails**: Registering dozens of MCP tools inflates system prompt token usage and can overflow client output buffers when fetching full pages. Best-in-class MCP servers mitigate this via **URL query-parameter tool scoping**—such as Jina's `?include_tags=search,read&max_tokens=50000`, Exa's `?tools=web_search_exa,web_fetch_exa`, Bright Data's `?groups=scrapers&tools=search_engine,scrape_as_markdown`, and You.com's `?tools=you-search`—or via Markdown output compression like SerpApi's `output=md` (which cuts SERP payload tokens by 50%–90%) ([Exa MCP Repo](https://github.com/exa-labs/exa-mcp-server), [Jina MCP Repo](https://github.com/jina-ai/MCP), [Bright Data MCP Registry](https://github.com/mcp/brightdata/brightdata-mcp), [SerpApi MCP Integration](https://serpapi.com/integrations/mcp)).
